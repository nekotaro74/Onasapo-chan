## 概要

本リポジトリは、Gemini PWA（<https://github.com/titan823/geminipwa>）を個人的にフォークし、挿絵生成機能（ComfyUIに接続）と読み上げ（Irodori TTS ServerなどのOpenAI互換のみ）機能を追加したものです。

自前の API キーを用いて Chat AI とやりとりを行うためのアプリです。

## 利用方法（PWA）

本 PWA はブラウザから以下の URL にてご利用いただけます。

<https://nekotaro74.github.io/Onasapo-chan/#chat>

使い方や不明点については、本リポジトリの `index.html` の内容を Google AI Studio 等で AI に提示のうえ、お尋ねください。

質問例：「この PWA の初めての使い方を教えて」「API キー・システムプロンプト・ダミープロンプトとは何か」「ユーザーデータの扱いはどうなっているか」

ローカルで使いたい方は、このリポジトリの全ファイル（.ZIP）をダウンロードしてご利用ください。（サイト上部の緑の「Code」から「Download ZIP」）

1. 任意のフォルダに展開する
2. フォルダ内の「__winlocal.bat」を起動
3. bat のウィンドウが開いている間はローカル http サーバーから index.html へアクセス可能

## GitHub Pages で使うためのセットアップ（挿絵生成・読み上げ）

導入方法は [docs/挿絵生成と読み上げの導入手引き.md](docs/挿絵生成と読み上げの導入手引き.md) をご覧ください。

挿絵生成（ComfyUI）と読み上げ（TTS サーバー）は、**利用者自身のマシンでサーバーを起動していること**が前提です。GitHub Pages 上のこのアプリ（https オリジン）から、利用者のローカル・LAN・Tailscale にあるサーバーへブラウザが直接接続します。中継サーバーは使いません。

⚠️⚠️⚠️⚠️⚠️ ComfyUI には認証がありません。`--enable-cors-header` を付けた ComfyUI を外向きに開く設定（ルーターでポートをインターネットへ転送するなど）は避けてください。

## データと API キーの扱い

- API キーは**利用者のブラウザ内（IndexedDB）にのみ**保存します。本アプリはサーバーを持っていません。キーは設定で選んだ API へブラウザから直接送られるだけで、リポジトリや外部サーバーへ書き出すことはありません。
- チャット履歴と設定も同じくブラウザ内の IndexedDB に保存し、サーバー経由の同期はしません。
- ブラウザが通信するのは、設定で選んだ API（Google / Anthropic / OpenAI / DeepSeek / xAI など）、利用者が URL を入力したエンドポイント（ComfyUI・TTS）、およびページ読み込み時に jsDelivr から読む DOMPurify と Mermaid だけです。中継サーバーは使いません。

## 変更点・仕様・連絡事項

⚠️ の数は重要度を表します。

### 最重要

- 応答のストリーミング表示に追従してスクロールしません。LLM の受信中は、ユーザーが自分で動かしたスクロール位置をそのまま保ちます（「メッセージ送信時に自動スクロールする」は送信時のみ効きます）。
- ⚠️⚠️⚠️⚠️⚠️ 過去のセッション履歴やプロンプト等の重要なデータは、各ユーザー様の任意のタイミングでバックアップしていただきますようお願いいたします。本アプリはアプリ内での恒久的なデータ保存や自動バックアップを意図しておりません。

### 挿絵生成（ComfyUI）

クラウド LLM の応答受信が完了した直後に、直近のシーンに合う挿絵を ComfyUI で生成します。
SillyTavern の Image Generation 拡張における「The Last Message」だけを模倣した実装です
（Yourself / Your Face / Me / The Whole Story / Background / Free mode 等は今回ありません）。

流れは SillyTavern と同じです。

1. 本編の応答が完了する
2. **その応答で初めて挿絵を作る場合だけ**、同じ LLM に quiet な画像プロンプト生成を1回だけ依頼する
   （直近メッセージの視覚情報だけをカンマ区切りキーワードにする。感情・性格・思考・セリフは無視し、
   名前でなく代名詞か male / female などの中立名詞を使う）
3. 返文を整形し、共通プレフィックス・キャラ外見プレフィックス・ネガティブプロンプトと合成する
4. API 形式ワークフローのプレースホルダを差し替え、`POST /prompt` に送る
5. `prompt_id` を `GET /history/{prompt_id}` でポーリングし、出力画像を `GET /view` で取得する
6. 画像をその応答メッセージの直下に表示し、チャット履歴へ永続化する

**再生成は quiet プロンプトを作り直しません。**保存済みの画像プロンプトをそのまま ComfyUI へ送るため、
クリックから ComfyUI の `got prompt` までの間にクラウド LLM は入りません。
初回生成・再生成では、コンソールに `[挿絵]` で起動時刻・プロンプト確定・`POST /prompt` 送信・
history 完了の各時刻（起動からのミリ秒）を出すので、待ちがどこにあるかを実機で確認できます。

**挿絵生成の推論に送る会話履歴は、既定で直近12往復に絞られます。**quiet 生成には本編の会話履歴を文脈として
渡しますが、全件を送ると長い会話で入力トークンが会話長に比例して増え、モデルの context window を超えて失敗します。
AI応答1回とその直前のユーザー入力を1組として数え、12 なら直近12往復が対象です。
「設定 → 挿絵生成（ComfyUI）→ 挿絵生成用プロンプト」の `挿絵生成の推論に使う履歴の往復(入力→応答)数` で変えられ、
**0 で全件送信**（空欄は 12 として扱います）。挿絵を付ける応答そのものは必ず送られます。
さらに内部の文字数上限（24,000 文字）で、往復数内でもさらに古い方を省略します。
設定の「デバッグ（挿絵生成用プロンプト）」には `直近 N 往復（会話全体では M 往復）` と表示されます。

設定は「設定 → 挿絵生成（ComfyUI）」にあります。生成タイミングは自動 / 手動で切り替えられ、
入力欄付近のボタン（`絵:自動` / `絵:手動` と `絵`）からも操作できます。

- ⚠️⚠️⚠️⚠️⚠️ ComfyUI はブラウザから直接叩くため、**`--enable-cors-header` を付けて起動する必要があります**。起動オプション（`--listen` 付き）と Tailscale 用の設定は、正本である [docs/挿絵生成と読み上げの導入手引き.md](docs/挿絵生成と読み上げの導入手引き.md) をご覧ください。
- ComfyUI base URL は末尾スラッシュを正規化します。PCだけで使うなら `http://127.0.0.1:8188`、スマホや別PCから Tailscale 経由で使うなら `http://{Tailscale IP}:8188` です。GitHub Pages の公開オリジンから接続するには、**ブラウザのローカルネットワークへの許可**が必要です。許可を出さない場合はローカル起動（`__winlocal.bat`）での動作確認を推奨します。
- 貼り付けるのは **API 形式**のワークフロー JSON です。UI 形式（`nodes` / `links` を持つ形式）は理由付きで拒否します。
- ワークフローは**複数登録**できます。一覧で「使用中」を切り替え、追加・改名・複製・削除、JSON の書き出し・読み込みができます。
  旧バージョンで 1 件だけ保存していたワークフローは、起動時に「移行されたワークフロー」として自動登録されます。
- **同梱の規定ワークフロー**を1件用意しています（`CheckpointLoaderSimple` → `CLIPSetLastLayer` → `CLIPTextEncode` ×2 →
  `EmptyLatentImage` → `KSampler` → `VAEDecode` → `SaveImage`）。SillyTavern 既定ではなく、本アプリが制作した初期値です。
  VAE と CLIP はチェックポイントの出力を使うため VAELoader / TextEncoderLoader 不要で、**LoRA ノードは含まれません**。
  ComfyUI の `loras` フォルダが空でもそのまま生成できます。設定の「ワークフロー一覧」から消しても、
  0 件になった場合は起動時に同梱ワークフローが戻ります。
- 書き出す JSON は `JSON.stringify(obj, null, 2)` で整形します。ファイル名はワークフロー名に日付と時刻を付けます
  （例: `myflow-20261005-143012.json`）。同じ日の複数書き出しでも上書きしません。
  読み込んだ JSON は整形されたまま編集欄に改行付きで表示されます。
- 差し込みは **JSON をパースしたうえで文字列値の中身だけ**を処理します。ワークフローを壊しません。
  - 値そのものを差し込む箇所は `"text": "%prompt%"` のように書きます。数値・真偽値は quotes なしで入ります（`"seed": "%seed%"` → `42`）。
  - 文中へ埋め込んでも置換されます（`"text": "masterpiece, %prompt%"` → `masterpiece, best quality, ...`）。
- 使用可能なトークン: `%prompt%` `%negative_prompt%` `%model%` `%vae%` `%text_encoder%` `%sampler%` `%scheduler%`
  `%steps%` `%cfg%` `%denoise%` `%clip_skip%` `%width%` `%height%` `%seed%` `%user_avatar%` `%char_avatar%`
  と LoRA の `%lora1%`〜`%lora4%` / `%lora_str1%`〜`%lora_str4%`。
  **CFG scale は `%cfg%` だけ**です（`%scale%` は廃止しました。残っていると未対応トークンとして検出され、生成が止まります）。
  `%clip_skip%` は SillyTavern と同じく**負の値**として ComfyUI へ渡します（設定には正の値を入力します）。
  `%user_avatar%` / `%char_avatar%` はアプリの設定アイコンを base64 で差し込みます（未設定なら 1x1 PNG）。
- **カスタム プレースホルダ**を任意数登録できます。find に `outfit`、replace に `1girl, school uniform` と書くと、
  ワークフロー内の `%outfit%` へ差し込まれます。replace 内の `{{char}}` / `{{user}}` は表示名に置換されます。
- 編集画面に**プレースホルダ検出**（✅ 検出 / ❌ 未検出）を表示します。
- **未対応のプレースホルダが残っている場合、ComfyUI へは送らずローカルでエラーにします**（トークン名を列挙）。
  このチェックは LLM を呼ぶ前にも走るため、不正なワークフローで API トークンを消費しません。
- モデル / VAE / テキストエンコーダ / Sampling method / Scheduler / LoRA は、接続先の ComfyUI の `/object_info` を
  **「接続確認＆モデル一覧取得」**でまとめてプルダウンに反映します。`/system_stats` で接続OKを先に出し、その後に
  `/object_info` を取りに行くので、一覧が重くても疎通結果はすぐ分かります。一覧は常に強制取得です。
  取得に失敗しても保存済みの値は残り、サーバーに無い値も消しません。
  **モデル・VAE・テキストエンコーダはファイル名を省略せず表示します**（拡張子や `_` を読みやすく置き換えません）。
  解像度プリセット、Sampling Steps、CFG scale、幅・高さ、Denoise、CLIP Skip、Seed は直接入力します。
  解像度プリセットの「カスタム」は「カスタム（上の幅・高さを使う）」と表示します。
- **生成パラメータの既定値**は Sampling method `euler` / Scheduler `simple` / 幅・高さ 1024 x 1024 /
  解像度プリセット「1024 x 1024 (SDXL)」/ Steps 8 / CFG scale 1.0 / Denoise 1 / CLIP Skip 1 / seed -1 です。
  既に設定を保存済みの場合は保存した値が使われます（既定値の変更は新規・未保存の設定にだけ反映されます）。

#### LoRA（最大4個）

LoRA の一覧も**「接続確認＆モデル一覧取得」で一緒に取ります**（`/object_info` の LoraLoader から取得し、そこに一覧が無い
古い ComfyUI では `GET {base}/models/loras`（または `/loras`）へフォールバックします）。取得した一覧は生成経路の
キャッシュにも入るため、生成時の再取得は走りません。4つのスロットで選びます。既定はすべて「使わない」です。

- **同梱の規定ワークフローには LoRA ノードを入れていません。**loras フォルダが空でも従来どおり生成できます。
- `%lora1%`〜`%lora4%` と `%lora_str1%`〜`%lora_str4%` は、あなたのワークフローに書かれている場合だけ使います。
  `%lora_strN%` は `strength_model` と `strength_clip` の両方に同じ値を入れます。
- **使うスロット**は、選んだファイル名と入力した強度をそのまま入れます。loras フォルダが空のときは送らず
  「LoRAを使うには ComfyUI の loras フォルダにファイルが必要です」と表示します。
- **使わないスロット**で一覧にファイルがあるときは、ノードの形は変えず、一覧の先頭の実在ファイル名と強度 0 を入れます。
  標準 LoraLoader は両方の強度が 0 ならファイルを読まず素通しし、`LoraLoaderModelOnly` は `strength_model` が 0 なら同じです。
- **使わないスロット**で loras フォルダが空のときは空文字を送りません。その LoraLoader ノードだけを外して
  `model` / `clip` を受け先へ直結し、ワークフロー全体は書き換えません。
- **対応 LoRA は 4 個まで**です。さらに、そのワークフローが受け取れる数（`%loraN%` を参照する LoraLoader ノードの数、
  または rgthree の `lora_1`〜`lora_4` の数）を超える番号のスロットは**選べません**。LoRA ノードの無いワークフローでは 4 つとも無効になります。

#### 表示・削除・全画面

- 挿絵の表示幅はその応答フィールドの横幅に合わせます。
- **1つの応答に複数枚持てます。**再生成しても古い画像は消えません。`◀` で古い画像、`▶` で新しい画像、
  左右スワイプでも切り替えます（縦スクロールはページに渡るので奪いません）。
- **画像を受信した瞬間も、◀▶ やスワイプで切り替えた時も、スクロール位置は動きません。**
  切替は表示中の 1 枚だけを差し替え、画像の復号でブロックの高さが一瞬潰れてビューが飛ぶことはありません。
- 「この画像を削除」は表示中の1枚だけ消し、「この画像を本当に削除しますか？」とアプリ内ダイアログで確認します。
  「この応答の画像をすべて削除」は「この応答に対して生成された画像を全て削除しますか？」で確認します。
- 画像をクリック（タップ）すると全画面になります。ホイールとピンチで拡縮でき、閉じるのは ✕ ボタンか画像外のタップだけです
  （拡縮中のタップでは閉じません）。
- 画像は ComfyUI 側の一時 URL ではなく、取得したバイトを data URL として履歴に保存します。
  履歴が肥大化しないよう、保存前に最大辺と最大バイトで縮小します。
- 挿絵の失敗は本編テキストと分離して、そのメッセージ直下にだけ表示します。ComfyUI が落ちていてもチャットは使えます。

#### 画像プロンプトの編集

- 画像下の「▶画像プロンプト」に**コピーボタン**があり、展開中は文章を編集できます。
  編集した内容は保存され、その後の再生成はその文字列を使います（「この文章で再生成」でも即再生成できます）。
- 「画像プロンプトを送信前に編集する」をオンにすると、**初回の quiet 生成後・送信前**にダイアログで編集できます。
  キャンセルした場合は ComfyUI へ送りません。再生成では保存済みの文章をそのまま使うため、この編集は走りません。
- 入力欄付近の `画` ボタンは、画像の無い応答なら初回生成、画像済みの応答なら「挿絵を再生成」と同じ動作です。

node tools/e2e.js              # モック ComfyUI に対して headless Chrome で実際に走らせる
node tools/local-launch.js     # 同上。file:// で開いたときの案内と、http:// では出ないことを確認する

### 読み上げ（OpenAI Compatible TTS）

SillyTavern の TTS 拡張の操作を模倣した読み上げ。**プロバイダは OpenAI Compatible のみ**です。

- 設定は「読み上げ（TTS）」グループ。エンドポイント / APIキー / モデル名 / 有効な参照ボイス一覧（カンマ区切り） / 速度を IndexedDB に保存します。
- 呼び出しは `POST {endpoint}/audio/speech`、body は `model` / `voice` / `input` の 3 つだけ。`Authorization: Bearer` は APIキーを設定した場合だけ送ります。
- エンドポイントには末尾スラッシュ除去後、`/audio/speech` が無ければ自動で足します（`https://api.example.com/v1` → `…/v1/audio/speech`）。
- 速度は本文に含めず、再生側の `playbackRate` で掛けます。サーバーの対応に依存せず、未知のフィールドを嫌う互換実装でも動きません。
- APIキーはこのアプリの IndexedDB にだけ保存します。ファイルへの書き出しには出さず、リポジトリにも含めません（既定は空）。

#### 操作

| 操作 | 場所 |
| --- | --- |
| 有効／無効 | 設定の「読み上げを有効にする」 |
| 自動読み上げ | 設定のチェック、または入力欄付近のメガホンボタン |
| 停止 | 設定の「停止」ボタン（キューと未送信の段落を破棄して現在の音声も止める） |
| 速度 | 設定のスライダー 0.25〜4.00 倍 |
| 個別に読む | 応答ごとのメガホンボタン（読み上げ済みでも押し直せる） |
| 参照ボイス一覧 | **「接続確認＆ボイス一覧取得」でサーバーの一覧 API を叩き、返ってきた voice をチェックボックスに並べます**。チェックした物だけが話者選択の候補です。一覧の fetch 自体が接続確認を兼ねるので、Irodori 固有の `/health` は使いません（`GET {base}/v1/audio/voices` を先に、無いサーバーは `GET {base}/v1/voices` を試します）。Irodori は Voices フォルダのファイル stem を返し、種別（音声 / latent / SI / no_ref）もラベルで出します。`no_ref` 専用は既定で有効にしません。一覧 API を持たないサーバーでは「接続OK（…非対応の可能性）」と示し、**閉じた「詳細」のカンマ区切り入力**で従来どおり編集できます。一覧は 5 分キャッシュしますが、ボタンは常に取り直します。設定の再描画での自動取得はありません |
| テスト再生 | 一覧とは別に、短い文を 1 回だけ合成して再生します。voice は 設定のデフォルト → チェック済み最初 → 一覧の先頭 の順に決めます。読み上げキューとは別に鳴り、「停止」の対象外です |

入力欄付近のメガホンボタンは **自動が赤地に白**、**手動がグレー地に白**です。自動は最初の段落が確定した時点から読み始めます（中断・エラー完了では読みません）。

再生はキューで順に鳴らし、重ねません。1 件の合成が終わって再生が終るまで次を取りに行きません。

#### 段落ごとの読み上げ

応答全文の受信完了を待たず、**受信済みの段落から順に** TTS へ送ります。段落は空行区切り、空行が無い応答では改行区切りです。

- ストリーミング中は区切りまで届いた段落だけを送り、末尾の未完了段落は次の区切りか受信完了まで保留します。
- 閉じていないコードブロックの中は送しません（フェンスが閉じた時点でまとめて除かれます）。
- 話者検出・地の文を読まない設定・コードブロック等の除外は、段落ごとに今までどおり適用します。
- 手動読み上げと、受信済み応答のメガホンも、先頭の段落から同じ順で送ります。
- 停止すると、まだ TTS へ送っていない段落も破棄します。

#### 読まないもの

コードブロック（``` と ~~~）、インラインコード、URL、Markdown の装飾（強調・リンク・見出し・箇条書き・引用・表・HTMLタグ）、そして**挿絵プロンプト欄**です。挿絵プロンプトは `message.illustration.prompt` にあり応答本文 `message.content` とは別物なので、読み上げ本文には入りません。

加えて送信前の正規表現フィルタを 1 本持てます（SillyTavern の `apply_regex` 相当）。パターンは全角・半角の正規化**後**のテキストに見ます。

#### 話者割当

設定で手入力します（SillyTavern の voice map と同じ発想）。デフォルトボイス＝地の文、汎用ボイス＝話者名の無い引用や括弧、登場人物 1〜5 に名前とボイスを割り当てます。

検出は**完全一致**で**最長名を優先**し、名前は行頭・改行後・文境界に現れたものだけ見ます。半角と全角のスペース、`()` と `（）`、`:` と `：`、`"` と `”` は同じとして扱います。

同じ行での優先順:

1. 名前 + 心理描写 + セリフ
2. 名前 + セリフ（「」『』または引用符）
3. 名前 + 心理描写だけ
4. 名前 + `:` または `：` + その行の残り
5. 話者名なしの引用・心理描写は汎用ボイス
6. 残りは地の文

名前の直後に引用・括弧・コロンが続かない場合（例: `まゆみは笑った。`）、その名前は地の文の一部として扱います。

「地の文を読まずセリフだけ読み上げる」をオンにすると、地の文をキューに入れません。

#### CORS

ブラウザから直接叩くため、サーバー側で CORS が許可されている必要があります。届かなかった場合は挿絵生成と同じ形式で対処法を案内します（手動で押した場合はダイアログ、自動のときは設定欄の状態表示）。

Irodori TTS Server での `IRODORI_CORS_ORIGINS` の設定と、PC用 / Tailscale 用のエンドポイントの書き分けは、正本である [docs/挿絵生成と読み上げの導入手引き.md](docs/挿絵生成と読み上げの導入手引き.md) をご覧ください。

実装メモ: [docs/tts-notes.md](docs/tts-notes.md)

## DeepSeek について

- ⚠️ DeepSeek API はインターネットから情報を取得する機能を提供していません。API 経由での画像やファイルの直接解析も非対応です。
- 2026-10-07 時点の現行 model id は `deepseek-flash`（DeepSeek-V4.1-Flash）と `deepseek-v4-pro` です。設定のモデル一覧は **model id をそのまま表示**しており、DeepSeek 側で世代交代しても PWA の書き換えは不要です。`deepseek-v4-flash` は世代廃止で、DeepSeek が現行モデルへ転送します。旧 `deepseek-chat` / `deepseek-reasoner` は 2026-07-24 に廃止され、現在は使用できません（一覧では「世代廃止」「廃止済み」の欄に分けてあります）。
- **API エンドポイントの既定は `https://api.deepseek.com` への直接接続です。** DeepSeek API はブラウザからのクロスオリジン要求（CORS）に対応しているため、中継サーバーは不要になりました（従来既定だった独自中継 URL は削除しています）。プロキシや互換 API を使う場合のみ「API エンドポイントURL」を入力してください。
- **Thinking Mode と Reasoning Effort を設定画面に追加しました。**「思考プロセス」で Thinking を切り替え、effort は `low` / `high` / `max` から選びます（公式の既定は Thinking 有効・`high`）。Thinking をオフにした場合は `reasoning_effort` を送らず `thinking: {"type": "disabled"}` のみを送ります。思考内容は `reasoning_content` で返り、Include Thoughts をオンにすると表示します。
- **パラメータが効くかどうかは Thinking の ON / OFF で変わります（2026-10-07 時点の公式 API。設定画面にも同じ注釈を置いてあります）。**
  - `max_tokens` … ON・OFF どちらでも効きます。
  - `temperature` … **Thinking OFF のときだけ効きます**。Thinking ON ではエラーにはなりませんが効果はありません。
  - `top_p` … **Thinking ON のときだけ効きます**。有効範囲は 0.95〜1.0 で、0.95 未満は 0.95 として扱われます。Thinking OFF では 1.0 に固定され値は無視されます。
  - `presence_penalty` / `frequency_penalty` … ON・OFF どちらでも効果はありません（公式に廃止済み扱い）。
  - `logprobs` … 設定すると `top_logprobs` に関するエラーになります。
  - 文字送りの速度を制御する専用のパラメータは提供されていません。
  - 「API エンドポイントURL」で**互換 API を指定したときは上記が当てはまりません**。接続先の仕様に従います。
- ※ DeepSeek が提供する API はすべて有料です。

# AI間会話モード（セッション間リンク）
概説:2つのチャット履歴を繋げ、一方のAIの返事をもう一方のAIへの質問として使い、AI同士の会話を仲介する機能です。バックグラウンドでもう一方のセッションを動かす事で行います。
セッションを跨ぐことでキャラクター同士を会話させたり、一方のAIにユーザーの代理を演じさせ自動で応答させたり、美咲先生同士を戦わせたりできます。
使い方:
1. 有効化: 設定（⚙️）で「セッション間リンク機能」をオン。
2. リンク: 履歴画面（☰）で、会話させたい2つの履歴の「🔗」ボタンを押してリンク（緑とピンクで表示）。
3. 実行: リンクしたどちらかのチャット画面を開き、フッターの「👥」ボタンを押す。
    * 現在のAIの返事が、もう一方のAIへの質問として自動送信。
    * その応答が、さらに現在のAIへの質問として自動送信され、最終結果が表示されます。
    * 処理中は「AI間会話処理中…」などと表示されます。
 - 各履歴には、このAI間のやり取りが通常のメッセージとして記録されます。
- AI同士の会話を行うという点をAI達に認識させるためには前振り・導入をする必要があります。
例:あなたにはこれから、他のAIと会話してもらいます。お題は“熊と虎のどちらが強いか”です。次の入力以降はユーザーの入力ではありません。では、始めましょう。）
- ※注意点:本機能は試験的かつ遊戯的な機能です。また、自明な点ですが、リンクに用いる両セッション分のトークンが消費されます。動作確認は必ず無料モデルを用いて検証してください。
- 出入力以外のリンクは行わないため、メッセージの編集やリトライなどをしたい場合、双方のセッションにて手動でメッセージを整える操作を行う必要があります。
- リンク中はどちらか一方のセッションのみを使用することを推奨いたします。
- ※ Max Tokensの設定が足りないと失敗します。（特に推論機能を用いる場合）また、一方の応答が失敗したり、空の応答が返った場合も失敗します。

# Gemini PWA Client

このリポジトリは、PWA（Progressive Web App）で作られたGemini APIのクライアントアプリケーションです。  
PWAとは実体がhtmlなだけの簡易アプリです。ブラウザがあれば使えます。
単純な文字チャット機能だけでファイルや画像関連の機能はありません。

## 使い方

Github Pagesで公開されたこのページにアクセスするだけです。  

[index.htmlへのリンク(Github Pages)](https://nekotaro74.github.io/Onasapo-chan/)
※このリポジトリの内容が静的にアクセスできる

1. GeminiのAPIキーを準備。
2. 上のリンクにアクセス。
3. 設定画面にGemini APIキーを設定して設定を保存。
4. チャット画面からチャット。

## PCのローカルでホストする
Webサイト上のは信用ならんからローカルで使いたい！という人はWindowsのみ下記の方法で使えます。
1. このリポジトリの全ファイルをダウンロードして同じフォルダ内に配置  
（サイト上部の緑の「Code」から「Download ZIP」）
2. __winlocal.batを起動
3. batのプロンプトが開いている間はローカルhttpサーバーからindex.htmlへアクセス可能

⚠️ ローカルで使用する場合は、`index.html` を直接ダブルクリックして開かないでください。  
ブラウザは `file://` で開いたページから `marked.js` などを読み込めないため、アプリは起動しません。  
ローカルで使う場合は、必ず `__winlocal.bat` をダブルクリックして起動してください。  
（ポート番号を変えたい場合は `__winlocal.bat` 内の `http://localhost:8072/` を編集します）

## ブラウザからPWAをアプリとしてインストール(任意)
PWAアプリとしてインストールするとアプリアイコンを作成できます。  
ブラウザにより挙動は違いますが、アドレスバーの横や設定ボタンなどから「XXをインストール」の項目を探してください。    
(モバイル用Chromeなら「ホーム画面に追加」が上記操作に相当）  
インストールしなくてもブラウザはPWAアプリをPWAアプリとして扱います。

## ファイルの説明
* manifest.json : PWAアプリの定義
* index.html : アプリそのもの
* sw.js : PWAサービスワーカー(PWAアプリとしてのファイルキャッシュなどを管理)
* marked.js : マークダウン表示用ライブラリ(MIT Lic)  

sw.jsのおかげで一度アクセスしたらブラウザ内に必要ファイル(「index.html」や「manifest.json」など)がキャッシュされる  
一度キャッシュされたら、設定から更新しない限り更新されない

## データの保存と通信について
* 設定やチャット履歴含む全てのデータはローカルのIndexedDBに保存されます。  
（ブラウザの中のデータベース。Github Pagesの当リポジトリのオリジン)
* 通信はGeminiAPIとしか行いません。(検索機能はGemini側の機能です)
* 履歴は履歴一覧からテキストファイルとしてエクスポートできます  
逆(インポート)は今のところ~~できません~~できます
