# Onasapo-chan 更新履歴

本リポジトリ（Onasapo-chan）での追加・改変の履歴です。PWA 内の「更新内容」リンクは本書の GitHub Pages 版（<https://nekotaro74.github.io/Onasapo-chan/docs/更新履歴.html>）を開きます。

フォーク元リポジトリ [Gemini PWA](https://github.com/titan823/geminipwa) 由来の履歴は README.md に残しています。更新を書くときは本書の**最新が上**になるよう追記し、`sw.js` の `CACHE_NAME` を上げてください。

### 2026-10-13（バージョン 0.27on (Onasapo-chan)）
- **アプリの更新をお知らせするバナーを追加しました。** 新しい版が配信されると、チャット・履歴・設定の各画面の上部に「アプリの更新があります。」と **更新する** / **あとで** のボタンが表示されます。
  - **更新する** を押すと新しい版が適用されてページが再読み込みされます。**あとで** を押すと古い版のまま作業を続けられ、次回このページを開いた時に再び表示されます。
  - 仕組み: `sw.js` の `CACHE_NAME` を上げると新しい Service Worker がインストールされますが、インストール直後に呼んでいた `skipWaiting()` をやめました。新しい版は **waiting** 状態で待機し、ページ側がそれを検知してバナーを出します。「更新する」を押された時だけページから Service Worker へ `skipWaiting` を伝え、その後に再読み込みします。従来はインストールと同時に古い版が置き換わっていたため、**作業中に勝手に更新が適用されることはありません**。
  - ブラウザはページを開き直した時にしか `sw.js` を確認しないため、**30分ごと**と**タブに戻ってきた時**に `registration.update()` で積極的に確認します。開きっぱなしのタブでも更新に気付けます。
  - ヘッダーは `position: absolute` で画面上部に置かれているため、バナーが出ている間だけヘッダーをバナーの高さだけ下へずらします。ヘッダーのボタンは隠れません。
  - 設定内の「アプリを更新 (キャッシュクリア)」ボタンはこれまでどおり使えます。Service Worker のキャッシュ名を `onasapo-chan-cache-v41` へ更新しました。
- **挿絵生成の既定の画像プロンプトを手直ししました。**設定の「挿絵生成（ComfyUI）」→「挿絵生成用プロンプト」の初期値が変わります。すでに自分で編集している人はそのまま残りますので、新しい文章に変える場合はその下の「既定に戻す」を押してください。
  ① 冒頭を `これはチャット本編ではなく、画像生成プロンプトを作成する作業です。チャットの続き、説明、前置き、引用符は書かず、画像生成プロンプトだけを出力しなさい。` に変えました。挿絵生成の推論には**チャットの履歴と指示文だけが送られていて、システムプロンプトもキャラクターカードも入っていません**。そのため前版の `これまでの指示は無視しなさい。ロールプレイするな。物語を止めなさい。` は、そもそも無視すべき指示が存在しないのに敵対的な前置きを書いている形でした。作業の説明に置き換えています。
  ② **出力の並び順を変えました。1行目は人数のタグだけ**になり、**カメラ・写る範囲・場所・光は最後の1行にまとめて**書きます。前版はカメラが1行目と結びの両方に出ていて同じタグを2回書いていたので、その重複も消えました。人物文が長くなっても末尾の行は「思い出して書く」ではなく「穴埋めする」形になるため落ちにくく、仮に末尾から切れることがあっても**失われる順が重要度の順**になります（残ってほしいのは人数と人物の記述なので）。場面語を末尾1行に集約したことで、`standing in the classroom` のように**人物文へ場所が漏れる逃げも塞いでいます**。
  ③ **写る範囲を1つ書かせる**規則を増やしました（全身なら `full body shot`、膝上なら `upper body`、顔中心なら `close-up`）。前版は項目に `靴` を含めながら写る範囲を指定していなかったので、膝から下が写らない絵に靴のタグが乗る矛盾が起きていました。**全身を写さないときは靴と脚を書かない**と明記しています。
  ④ **手前の層は会話の中に実際に写る物があるときだけ**置く做法にしました。前版は1人用の形で `A [手前の物] sits in the foreground` が必須だったため、会話に無い椅子やコップを発明させていました。奥行きは「中間の人物と奥へ引く背景は必ず書く」文の側で作る形にし、手前の物が無いときは `The [背景] recedes behind them.` だけを書きます。
  ⑤ **カメラと光は、語彙を列挙せずに「選び方」で書く**做法にしました。カメラは `相手を上に見上げるなら低い位置、下に見下ろすなら高い位置、並んで立つなら目線`、光は `場所と時刻から選ぶ。光源がどこから来ているかを書く（後ろから、横から、上から）` という規則です。語彙を並べると**弱いモデルは並べた語しか使わなくなる**ため、会話から導出できる条件側に替えています。逆に弱いモデルが逃げ込む語は引力にならない禁止側で潰し、`cinematic, dramatic, beautiful, stunning, professional, highly detailed` を書かないとしました。
  ⑥ 人数タグの書き方を明確にしました。**同性別が2人以上なら `2girls` / `2boys`、異性別なら `1girl, 1boy`** のように1人ずつ性別を書き、1人のときだけ `solo` を添えます。前版は `1girl, solo` と `1girl, 1boy` の例しかなかったため、女性2人のときに `1girl, 1girl` が書かれうる形でした。`people` の禁止はそのままです。
  Service Worker のキャッシュ名を `onasapo-chan-cache-v40` へ更新しました。

### 2026-10-12（バージョン 0.27on (Onasapo-chan)）
- **挿絵生成の既定の画像プロンプトを、新しい文章へ差し替えました。**設定の「挿絵生成（ComfyUI）」→「挿絵生成用プロンプト」の初期値が変わります。すでに自分で編集している人はそのまま残りますので、新しい文章に変える場合はその下の「既定に戻す」を押してください。
  新しい文章は**指示文そのものを日本語**にしました（出てくる文章はこれまでどおり英語のタグ文のみ）。「最後のチャットメッセージを象徴する瞬間を1枚として切り取り、**ユーザーの視点から画面内に見えている人と物だけ**を書く」を冒頭に置き、続く規則で条件を並べます。主な点は次のとおりです。① **人物文の数を画面内の人数と一致**させ、`1girl, solo` や `1girl, 1boy` のように**性別と人数を記述**します。`people` という単語は禁止です。② **挿絵にふさわしい映画的なカメラアングルを必ず1つだけ**書きます。③ **奥行きはカメラと場所で作る**（手前の物や面・中間の人物・奥へ引く背景）。1人のときはその人物の層は1つだけです。④ 1行目はタグで、1人のときは `[性別], solo, カメラ1つ, 奥行き, 場所` の順になります。⑤ 2人以上のときだけ近い順に別の層へ置き、**片方は近くて大きく、もう片方は遠くて一部重なってよい**と重なりの扱いまで指定しました。左右は実際に左右であるときだけ書きます。⑥ 見えている人物ごとに1文で、「層・名前と作品・髪・目・上半身・下半身・靴・表情・その人だけの動作」の順に、**全員同じ項目を書き空欄にしない**。他人の色や服を流用せず、複数人では色を被らせません。接触するなら誰のどの手か腕かを書きます。⑦ **物語の進行状況から現在の衣類や衣類の状態を推論**させる規則を増やしました。衣類の状態には**身につけていないことも含む**と明記しています。⑧ 最後に動作を一文で言い、**場所・光・カメラで終える**形にしました。⑨ 前版にあった `160 語以内` の語数制限は外し、書く項目で密度を制御する做法に変えています。
  なお、**新しい既定文には `{{char}}` / `{{user}}` が含まれないため、既定文のままでは「表示するAI名」「表示するユーザー名」の名前はプロンプトへ挿入されません**（人物名は会話の履歴から読み取ります）。ご自分で文章を編集して `{{char}}` / `{{user}}` を書けば、これまでどおり送信直前に名前へ置き換わります。Service Worker のキャッシュ名を `onasapo-chan-cache-v38` へ更新しました。

### 2026-10-11（バージョン 0.27on (Onasapo-chan)）
- **挿絵生成の既定の画像プロンプトを、新しい文章へ差し替えました。**設定の「挿絵生成（ComfyUI）」→「挿絵生成用プロンプト」の初期値が変わります。すでに自分で編集している人はそのまま残りますので、新しい文章に変える場合はその下の「既定に戻す」を押してください。
  主な変更は次のとおりです。① 出力の長さを **160 語以内**に縛りました。Anima は 300 トークンを超えると末尾のタグが黙って落ち、LLM が書いた長い修飾文はプロンプト追従が落ちるため、長さそのものを指示で指定しています。② 人物ごとに1文ずつ、近い人から書く形はそのまま、**最後に「誰が何をしているか」を繰り返す文を無くしました**（同じ内容を何度も書くと特徴の混線につながるため）。③ **1人のときの出力形と2人のときの出力形をそれぞれ例として示す**ようになりました。1人の例は `solo` だけで完結し、2人目を誘発する構造にしていません。④ 1行目のタグは「人数・solo（1人のとき）・カメラ1つ・場所・時刻または天候」の順になり、**奥行きを示す語を1行目に書かなくなりました**。奥行きは手前の物体・人物の層・奥へ引く背景で作り、人物を背景へ回して作る做法は禁止のままです。⑤ `no` / `not` / `without` といった**否定語を使わず、あるものを書く**指示にしました（1人なら `solo`、誰もいない場所なら `empty`）。Krea 2 Turbo は CFG 1 でネガティブプロンプトがほぼ効かず、Anima もポジティブ側の否定を無視してそのものを出すことがあります。⑥ **キャラクター名と作品名は英語の通常の大小表記**にします（タグは小文字のまま）。Anima 公式の推奨に合わせました。⑦ `over-the-shoulder shot` はカメラの選択肢から外し、**もう1人の肩が実際に写っているときだけ**使える扱いにしました。Service Worker のキャッシュ名を `onasapo-chan-cache-v35` へ更新しました。
- **読み上げ中の応答を削除すると、再生がその場で止まり、TTS サーバーにもまだ合成していない文を作らせないようにしました。** これまで削除しても音声は最後まで読み上げられていました。
① 応答の「削除」とカスケード応答の「この応答を削除」では、キューに入っている断片を**削除した応答分だけ**除き、その応答を再生中なら中断します（別の応答を読んでいればそのまま読み続けます）。リトライで未来の会話履歴を消すときは捨てられる応答分を止め、新規チャット・別のチャットの読み込み・全履歴削除・全データ削除では全ての読み上げを止めます。
② 受信を OpenAI 互換の `stream_format: "sse"` に切り替え、**1 文ぶんの音声が順に届く**形にしました。TTS サーバーには中止用の API が無く、1 発 POST はクライアントが接続を切ってもサーバー側で全文の合成を走り切るためです（Irodori TTS Server で確認）。SSE ならサーバーは 1 文ごとに合成して送るので、削除時に接続を閉じた時点で残りの文は作られません（進行中の 1 文ぶんだけ完了します）。`stream_format` を無視して音声を返すサーバー（Kokoro 形式など）は従来どおり 1 本まとめて受け取り、400 で嫌うサーバーには以後 `stream_format` を付けません。受信は再生を待たずに先へ進みますが、再生は従来どおり重ねません。
あわせて、停止したときに `play()` が中断されて「読み上げに失敗しました」のダイアログが出るケースと、停止後に届いた取得結果が `playing` を書き戻して後続の再生と競合するケースを直しました。Service Worker のキャッシュ名を `onasapo-chan-cache-v33` へ更新しました。
- **Irodori 以外の OpenAI Compatible TTS サーバーでも読み上げが壊れないようにしました。** `stream_format` は OpenAI の仕様には無い拡張なので、① 未知の項目を 400 / 422 で嫌うサーバーには、エラー本文に項目名が出ていなくても `stream_format` を外して 1 回やり直す（嫌った原因が項目名だと分かった時点から、以後はそのサーバーへ付けません）、② SSE を返したのに音声断片が 1 つも来ないサーバー（Irodori と違う SSE の形）では、無音で終わるのではなく「TTS サーバーは SSE で応答しましたが、音声が 1 つも届きませんでした」と表示するようにしました。Service Worker のキャッシュ名を `onasapo-chan-cache-v34` へ更新しました。

### 2026-10-10（バージョン 0.27on (Onasapo-chan)）
- 設定の「挿絵生成（ComfyUI）→ 挿絵生成用プロンプト」で、`挿絵生成の推論に使う履歴の上限(文字数)` の注釈の下に **`※ 画像再生成時はプロンプトを使いまわしますのでノーコストです。`** を追加しました。再生成はクラウドLLMを呼ばず、保存済みの画像プロンプトをそのまま ComfyUI へ送ります。
「画像プロンプトを送信前に編集する」の注釈からは `※ 再生成は保存済みの文章をそのまま使うため、この編集は走りません（再生成時の文章は画像下の「▶画像プロンプト」で直せます）。` の1行を落としました。再生成時に文章を直せる件は、README 上部の「▶画像プロンプト」と送信前編集の説明に残しています。Service Worker のキャッシュ名を `onasapo-chan-cache-v27` へ更新しました。
- **挿絵生成に送る会話履歴は、既定で全件送信にしました。**これまで既定 12 往復で絞っていましたが、範囲外へ出た登場人物の外見の記述が効かなくなり、絵の人物が崩れることがありました。quiet 生成には本編の会話履歴を文脈として渡すので、消費トークンは通常のチャット1回と同じです。本家 SillyTavern にも履歴の範囲を決める数値設定は無く、Chat Completion 側のトークン予算（`Context Size` − `Response Size`）で古い方から捨てる形になっています。
`挿絵生成の推論に使う履歴の往復(入力→応答)数` の設定項目は無くし、設定の「挿絵生成（ComfyUI）→ 挿絵生成用プロンプト」には **`挿絵生成の推論に使う履歴の上限(文字数)`** だけを残しました。既定 0 で全件送信、数を入れると古い方から省略します。長い会話でモデルの context window を超える場合向けの安全弁で、単位を文字数にしている以外は本家のトークン予算と同じ役割です。挿絵を付ける応答そのものは必ず送られます。設定の「デバッグ（挿絵生成用プロンプト）」には送った往復数と設定した上限を表示します。Service Worker のキャッシュ名を `onasapo-chan-cache-v26` へ更新しました。

- **GPU の VRAM の目安を追記しました。** 導入手引きの 1 章と README 冒頭の概要に「VRAM の目安」の節を入れ、既定の Anima Base 系で 6GB、Irodori-TTS-v4.1-Small の `int8` 量子化で 4GB、タイミングをずらすなら 6〜8GB 程度、同時に動かすなら 10GB が最低ラインで 12GB あれば安心、という内容です。VRAM が足りない PC 向けに、近年の CPU なら Irodori-TTS-v4.1-Small の CPU 版のステップ数を下げるなどで実用になることも書いています（作者の実測）。
- **LoRA を「使用中」にした時点で選べるようにしました。** これまで、LoRA を受け取るワークフローへ切り替えた直後は LoRA 1〜4 のプルダウンが無効のまま残り、**「接続確認＆モデル一覧取得」を押して初めて選べる**、という順番になっていました。原因はワークフロー切り替え時の描画順です。LoRA の判定は編集欄の JSON を見るのに、編集欄が切り替え前のワークフローのままの状態で LoRA 欄を作り直していたため、切り替え前の JSON で「LoRA を使いません」と判定されていました（編集欄を先に反映させるよう修正）。
あわせて、**LoRA を受け取るワークフローを「使用する」にした時点で LoRA 一覧を裏から取りに行く**ようにしました（接続先が入力済みなら `GET {base}/models/loras` を取ります。ComfyUI が止まっていても切り替えは待たず、失敗時は LoRA 欄に理由を出すだけ）。「接続確認＆モデル一覧取得」で一覧をまとめて取り直す挙動はそのままです。同梱の Anima 用①は Turbo LoRA がノードに固定されているため、これまで通り LoRA 1〜4 は無効のままです。Service Worker のキャッシュ名を `onasapo-chan-cache-v24` へ更新しました。
