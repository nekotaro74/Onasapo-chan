# Onasapo-chan 開発変更履歴

開発者向けの変更履歴です。仕組み・関数名・Service Worker のキャッシュ名など、実装を追うための情報を残しています。ユーザー向けの案内は [更新履歴.md](更新履歴.md)（PWA 内の「更新内容」リンクが読むページ）にだけ書き、こちらには書きません。

更新を書くときは本書の**最新が上**になるよう追記し、`sw.js` の `CACHE_NAME` を上げてください。コミット本文にも同じ仕組みを書いておくと `git log` 側でも追えます。

### 2026-10-14
- **更新バナーの配色をテーマ非依存へ変更（CACHE_NAME v44）。** `background-color: var(--bg-header)` / `color: var(--text-light)` は、ヘッダーと同じ色で境界が分からないうえ、淡いテーマでは白文字が読めなかった（既定テーマ `#4a90e2` + 白でコントラスト 3.3:1、`pastel-pink` `#ff8fab` + 白、`pastel-rainbow` の明るいグラデーション + 白はさらに低い）。バナー専用の固定色にし、背景 `#fff4d6` / 文字 `#4a3400`（10.7:1）、リンク `#6b4a00`（7.4:1）、ボタン `#8a6100` + 白（5.5:1）、下辺 `#d8bd7a`、影は `rgba(0,0,0,0.25)`。テーマ変数経由だと各テーマの `:root` 上書きで変わるため、CSS に直接色を書いている。
- **同じタブでリトライするたびに競合確認が出ていた不具合（commit 9c7d6dc、CACHE_NAME v43）。** 競合検知は「DB の `updatedAt` > `state.loadedChatUpdatedAt`」だが、`updatedAt` だけを進めて基準を更新しない書き込みが2つあった。① `handleSend` が送信直前に `chatToSave` を `_getStore(CHATS_STORE,'readwrite')` へ直接 `put` していた、② `updateChatTitleDb()` がタイトル変更で `updatedAt` を進める。`dbUtils.noteOwnWrite(id, updatedAt)`（`id === state.currentChatId` のときだけ基準を更新）へ集約し、①は `dbUtils.putChatDirect(chatData)` として `dbUtils` へ切り出し保存成功時に同期、②も同期した。新規セッション作成直後は `loadedChatUpdatedAt` が `null` のままなので検知は働かない（`saveChat` 成功で入る）。
- **別タブによる上書きの検知（commit 225dfc6、CACHE_NAME v42）。** `state.loadedChatUpdatedAt` にこのタブが読み込んだ時点の `updatedAt` を保持し、`dbUtils.chatUpdatedByOtherTab(id)` が DB 上の更新が新しいか判定、`saveChat()` が保存前に `uiUtils.showCustomConfirm()` を出し、キャンセル then `appLogic.loadChat()` で他タブの版を開き直す。保存はセッション1件を `store.put` で丸ごと書き直すため、後から保存した側が先に保存した側の `illustration` を失わせていた。e2e.js の `CONFLICT_SCRIPT` に回帰テスト6件（修正なしで毎回 NG になることを確認済み。比較する `loadedChatUpdatedAt` は `Date.now() - 60000` で明示的に過去へ戻しており、ミリ秒差に依存させない）。

### 2026-10-13
- **更新バナー（CACHE_NAME v41）。** `sw.js` の `CACHE_NAME` を上げると新しい Service Worker がインストールされるが、インストール直後に呼んでいた `skipWaiting()` をやめ、**waiting** 状態で待たせた。ページ側が `registration.waiting` を検知して `.update-banner` を出し、「更新する」を押された時だけ SW へ `skipWaiting` を伝えて再読み込みする。`あとで` は古い版のまま続け、次回ページを開いた時に再表示。`updateBannerWaitingSw` で同じ版の繰り返し表示を防ぐ。
  - ブラウザはページを開き直した時にしか `sw.js` を確認しないため、**30分ごと**と**タブに戻ってきた時**に `registration.update()` を呼ぶ。
  - ヘッダーは `position: absolute` なので、`body.update-banner-visible` で `top: var(--update-banner-height)` を与えてバナーの高さだけ下へ押し出す（高さは `offsetHeight` から設定）。
  - 各画面（チャット / 履歴 / 設定）に1つずつ DOM があり、`elements.updateBanners` でまとめて出す。e2e.js は「更新内容」リンクが3画面分あることと `/docs/*.html` へのリンクを検査している。
- **既定の画像プロンプトを手直し（CACHE_NAME v40）。** ① 冒頭を「これは画像生成プロンプトを作成する作業です」の説明へ（挿絵生成の推論にはチャット履歴と指示文だけが送られ、システムプロンプトもキャラクターカードも入らないので、「これまでの指示は無視しなさい」は敵対する対象が無い前置きだった）。② 出力順を変え、1行目は人数タグのみ、カメラ・写る範囲・場所・光は末尾1行へ集約（前版はカメラが1行目と結びの両方）。末尾は穴埋め形にして、切れたとき失われる順を重要度の順にする。③ 写る範囲を1つ書かせ、全身を写さないときは靴と脚を書かない。④ 手前の層は会話に実際に写る物があるときだけ（前版は `A [手前の物] sits in the foreground` が必須で椅子やコップを発明させていた）。奥行きは「中間の人物と奥へ引く背景は必ず書く」側で作る。⑤ カメラと光は語彙の列挙ではなく導出規則（見上げ/見下ろし/並ぶ、場所と時刻と光源の方向）。弱いモデルが並べた語しか使わなくなるため。禁止側は `cinematic, dramatic, beautiful, stunning, professional, highly detailed`。⑥ 人数タグは同性別2人以上で `2girls` / `2boys`、異性別で `1girl, 1boy`、1人だけ `solo`。

### 2026-10-12
- **既定の画像プロンプトを日本語の指示文へ差し替え（CACHE_NAME v38）。** 出力は英語タグ文のまま。人物文の数を画面内の人数と一致させ `1girl, solo` / `1girl, 1boy` の形で性別と人数を書き、`people` は禁止。カメラは1つだけ。奥行きは手前/中間/背景の層で作る。2人以上は近い順に別の層へ置き、重なりの扱いまで指定。人物ごとに1文で層・名前と作品・髪・目・上半身・下半身・靴・表情・動作の順に空欄なく。他人の色や服を流用しない、複数人で色を被らせない、接触は誰のどの手か腕か。物語の進行から衣類と衣類の状態（身につけていないことも含む）を推論。最後に動作を一文、場所・光・カメラで終える。`160 語以内` の語数制限は外し、書く項目で密度を制御。`{{char}}` / `{{user}}` は既定文に含まれないため名前が挿入されない（人物名は履歴から読む）。

### 2026-10-11
- **既定の画像プロンプトを更新（CACHE_NAME v35）。** 長さを 160 語以内に縛る（Anima は 300 トークン超で末尾タグが落ち、長い修飾文は追従が落ちる）。末尾の「誰が何をしているか」の繰り返しを削除。1人用と2人用の出力形を例で示す。1行目は人数・solo・カメラ1つ・場所・時刻または天候の順で、奥行き語を書かない。否定語（`no` / `not` / `without`）を使わずあるものを書く（Krea 2 Turbo は CFG 1 でネガがほぼ効かず、Anima はポジ側の否定を無視する）。キャラクター名と作品名は英語の通常の大小表記（Anima 公式推奨）。`over-the-shoulder shot` はもう1人の肩が実際に写るときだけ。
- **読み上げの中断（CACHE_NAME v33）。** 応答削除・カスケード削除ではキューから削除した応答分だけ除き、再生中なら中断（別の応答なら読み続ける）。リトライは捨てられる応答分、新規チャット・別チャット読み込み・全履歴削除・全データ削除は全て停止。受信を OpenAI 互換の `stream_format: "sse"` へ切り替え（TTS サーバーに中止 API が無く、1発 POST は接続を切ってもサーバー側で全文合成が走り切る。Irodori TTS Server で確認）。SSE は1文ごとに合成して送るので、接続を閉じた時点で残りの文は作られない（進行中の1文ぶんは完了）。`stream_format` を無視するサーバー（Kokoro 形式等）は従来どおり1本まとめて受信、400 で嫌うサーバーには以後付けない。`play()` 中断で「読み上げに失敗しました」が出るケースと、停止後に届いた結果が `playing` を書き戻して競合するケースを修正。
- **Irodori 以外の OpenAI Compatible TTS（CACHE_NAME v34）。** 未知の項目を 400 / 422 で嫌うサーバーは `stream_format` を外して1回やり直し、項目名が分かった時点から以後付けない。SSE を返したのに音声断片が0件のサーバーは「SSE で応答しましたが、音声が 1 つも届きませんでした」と出す。
- **LoRA 注釈の整理（CACHE_NAME v29〜v32）。** 対象ワークフロー形式（ComfyUI 標準の LoraLoader を複数使う形）と rgthree の Power Lora Loader では `on: false` になるだけだと明示。アプリが管理するノードの説明を一番上へ移し `--text-error` で赤に。4行を削除して README の同節へ移記（一覧の裏取得、選択と強度をワークフローごとに覚える 等）。
- **DeepSeek の Max Tokens 上限既定 32768（CACHE_NAME v28）。** 空のときはスライダーの上限が実質無制限（99999999999999999）だった。空にすると 32768 へ戻る。入力値が設定として保存されていなかったので保存するようにした。他のプロバイダは従来どおり空＝実質無制限。
- **TTS の速度欄（CACHE_NAME v28）。** スライダーを横幅いっぱいに伸ばし、右に直接入力欄を付けた。入力値はスライダーへ追従し、確定で 0.25〜4 へ丸める。

### 2026-10-10
- **挿絵生成の履歴範囲（CACHE_NAME v26）。** 既定を全件送信へ（12往復で絞ると範囲外の出登場人物の外見が効かず絵が崩れた）。`挿絵生成の推論に使う履歴の往復数` の設定項目を無くし、`上限(文字数)` だけ残す（既定 0 = 全件、数を入れると古い方から省略）。本家 SillyTavern には範囲の数値設定が無く Chat Completion 側のトークン予算で捨てる形なので、同じ役割を文字数単位にしたもの。挿絵を付ける応答そのものは必ず送る。デバッグ欄に送った往復数と上限を表示。
- **設定注釈の簡略化とリンク化（CACHE_NAME v22、v23）。** 導入手引きへの案内をクリックで GitHub Pages 版を開くリンクに（`rel="noopener noreferrer"`）。
- **LoRA を「使用中」にした時点で選べるように（CACHE_NAME v24）。** ワークフロー切り替え時の描画順が原因で、LoRA 判定は編集欄の JSON を見るのに編集欄が切り替え前のままだった（先に反映させるよう修正）。切り替えた時点で `GET {base}/models/loras` を裏取り（接続先が入力済みなら。ComfyUI が止まっていても切り替えは待たず、失敗時は LoRA 欄に理由だけ出す）。同梱の Anima 用①は Turbo LoRA が固定なので LoRA 1〜4 は無効のまま。
- **VRAM の目安**を導入手引き1章と README 冒頭に追記。
